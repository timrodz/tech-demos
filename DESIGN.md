# Demo Lab Design System

This design system is inherited from Juan's portfolio at [github.com/timrodz/portfolio](https://github.com/timrodz/portfolio). The goal is to maintain visual consistency between the portfolio and Demo Lab's control panels, navigation, and supporting UI.

## Color Palette

### Primary Accents

- **Teal Primary**: `#0f766e` (teal-700)
- **Teal Secondary**: `#0d9488` (teal-600)
- **Orange Accent**: `#fb923c` (orange-400)

### Backgrounds

- **Cream Background**: `#fdfcfa` (stone-50/warm)

### Usage Guidelines

- Use teal for primary interactive elements, links, and focus states
- Orange accent for highlights, calls-to-action, or secondary emphasis
- Cream background for main content areas and control panels
- Demo canvas areas can use any colors the technique requires — the design system applies to **chrome only**

## Typography

- **Style**: Clean, modern, sans-serif
- **Hierarchy**: Clear, calm, readable
- Avoid italic serif decoration unless contextually appropriate for the demo

## UI Principles

### For Control Panels & Chrome

- Clean, minimal layouts
- Calm, professional aesthetic matching the portfolio
- Sufficient contrast for readability
- Keyboard-accessible interactive elements

### For Demo Content

- Canvas/demo content can be as vivid, experimental, or technique-specific as needed
- The design system does not constrain the demo itself — only the surrounding interface

## Anti-Patterns

Avoid generic AI-generated UI patterns:

- ❌ "AI beige" — bland, washed-out neutrals
- ❌ Status-chip soup — excessive pills and badges
- ❌ Pulsing dots and skeleton loaders (unless the demo requires them)
- ❌ Italic serif decoration that dilutes the modern feel
- ❌ Over-decorated interfaces that distract from content
